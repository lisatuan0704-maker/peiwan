TT 揪團角色圖片：網站端接線狀態

本次只完成網站目前角色的透明 PNG 匯出；TT 後端尚未取得，未發送任何 Discord 訊息。
既有訂單語音通知由 lobby-ui/order-voice.mjs 呼叫 api.tinytavern.tw 提供。
目前這份網站專案沒有上述服務的伺服器程式，不能在這裡直接修改機器人訊息。

呼叫方式（須在已建立角色的大廳頁面）：
  const png = await TinyTavernUI.exportCharacterPng();
  // 或 TTCharacterSnapshot.exportCurrent({scale: 4})
  // 回傳 image/png Blob，預設 256 x 256；可選 1–8 倍整數像素縮放。

輸出重用既有 drawDollTo：64 x 64、idle、睜眼、透明背景。
保留角色本身的裝扮及染色，不包含場景、座椅、名字、帳號資訊或獨立跟隨寵物。
只等待本次繪圖實際使用的圖片；逾時、缺圖、空白或無法讀取的跨來源圖片會失敗。
等待期間若帳號或穿搭改變，必須重新預覽。
此函式不會自行下載、上傳、修改角色或發送訊息；尚無公開揪團按鈕。

後端串接仍需完成：
1. 找到現有 TT 程式與部署設定（不要把 Discord Token 放進此公開網站專案）。
2. 在後端驗證登入身分，對照既有 Discord 綁定與角色資料。
   此前端圖片只是預覽，不是身分或時裝所有權證明；不可直接信任客戶端指定的角色 ID。
3. 若由 DC 指令發起，後端須讀取該人的授權角色及官方素材，用相同繪圖器輸出。
   若由網站發起，可先使用本函式預覽；伺服器仍須核對角色、限制圖片大小及格式。
4. 發布前明確告知：揪團圖片會讓 DC 上的參與者看見這個網站角色，取得本次分享同意。
   網站個人檔案不公開 DC 連結，不等於已同意在 DC 揪團卡公開角色關聯。
5. 建團與加入均確認當次揪團須知；每張公開揪團卡固定顯示簡短須知。
6. 將生成的 PNG 作為 TT 訊息附件，存成當次揪團的造型快照。
   舊揪團不跟著之後換裝更新。未取得分享同意時使用中性圖示。
7. 在測試頻道驗證發布、加入、滿員、取消及重試去重，再接入正式揪團功能。

訊息文案方向：
「有人在酒館留了一個位子，想找你一起玩 🍻」
自由揪團｜非付費陪玩服務
玩家自行組隊，店方不保證個別玩家的言行與相處體驗，亦不調解一般遊戲或人際爭執。
違反店規的行為仍可檢舉。

驗證：node tests/character-snapshot.cjs
需安裝 Playwright、pngjs 與 Chrome；TT_TEST_NODE_MODULES 可指定既有套件目錄。
測試以隔離角色資料執行，封鎖外部資料寫入與 WebSocket。
TT_SNAPSHOT_OUTPUT 可選填輸出測試 PNG 的資料夾。
